# Milestone 2 - Notes (the "3-4 lines")

**Not making up answers when the data isn't there.** Every tool returns an explicit status (`ok` / `not_found` / `error`). If no tool returned data, the reply is written by *code* (`abstain()`), so the model has no chance to improvise - e.g. `--brand-pink` returns "doesn't exist; closest names are --brand, --brand-dark". When data does exist, a grounding guard extracts every hex colour, `--variable` and number from the draft answer and requires each one to appear in the tool output; one unsupported fact rejects the draft, triggers one retry, then falls back to a deterministic answer built purely from the tool data. Tests use deliberately lying models to prove this.

**Checking it gives the same answer twice.** `check_consistency()` asks the same question twice from a clean state (the agent keeps no memory between questions) and compares the tool-call trace, a SHA-256 hash of the tool outputs, the exact answer text, and the *set of facts* in the answer. Tools are deterministic and the Claude backend uses temperature 0, so the verdict is `IDENTICAL`; if an LLM merely rewords, it reports `SAME_FACTS_DIFFERENT_WORDING`; if facts differ, `INCONSISTENT`. A test with a flaky model proves it is detected.
