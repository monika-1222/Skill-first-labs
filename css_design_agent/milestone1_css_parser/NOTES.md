# Milestone 1 - Notes (the "3-4 lines")

**What I extract and why.** Instead of dumping rules, `css_dna.py` extracts a stylesheet's *design DNA*: the colour palette (every colour normalised to hex, with `var()` chains resolved), typography and spacing scales (with the inferred 4px/8px grid and off-grid outliers), breakpoints, selector specificity, overridden/duplicated declarations, and a WCAG contrast ratio for every text/background pair. These are the facts a designer, reviewer or accessibility audit actually needs, and they are structured JSON that another program (my Milestone 2 agent) can query.

**Edge case I thought about.** `;` and `}` can appear *inside* strings and `url(data:...)` values (and `{ }` inside comments), so splitting a file on those characters breaks the parse. I wrote a small scanner that tracks quotes, parentheses and comments, and tests prove `content: "x;y}z"` and `url(data:image/png;base64,AA;BB}CC)` stay intact. Related cases handled: `var()` cycles and missing variables (reported as issues, not crashes), a last declaration without `;`, unterminated blocks, stray `}`, hex-looking text in `url(icon.svg#abc)`, and colour names inside `font-family: "Tomato Grotesk"` not being counted as colours.
